## Product bugs fixed by Tara

### Configured duration now has real live behavior

`durationMinutes` was previously persisted without live-session meaning.

The final integration:
- anchors the planned deadline to persisted session creation time;
- refreshes stored-session metadata after start/recovery/Quant reattach;
- shows a non-blocking reminder when the planned time is reached;
- never auto-terminates candidate work;
- hides the reminder while the interview is backgrounded/paused;
- immediately re-evaluates the wall-clock deadline when the live view returns;
- explains in New Interview that duration is a planning reminder, not an automatic cutoff.

### Normal-user Review/Sessions language

The merged tree still exposed implementation terms such as “bounded evaluation read,” “replay projection,” “authoritative event history,” “GROUND TRUTH,” and “metrics are non-authoritative.”

Tara replaces those presentation strings with ordinary product language without changing evaluator/replay/session authority, bounds, or diagnostics.

### Release documentation truth

The merged release docs still described a pre-v0.1 product:
- legacy-only Ramsey launch;
- no selectable Oxford/Quant modes;
- no live Antigravity provider execution;
- no physical audio path;
- fake-only semantic vision;
- manual installation of the pinned Python dependency graph into the user's interpreter.

Tara updates README and Windows release documentation to match the actual merged product:
- normal Oxford/Quant launch UI;
- supervised Antigravity execution when installed/authenticated;
- physical local voice path;
- managed local vision;
- external 64-bit CPython 3.12/3.13 prerequisite only;
- app-owned isolated Python environment and separate Python/voice/vision setup actions from Settings.

### Unrelated timeout widening reverted

Hosted-Windows runner starvation led #120/#121 to widen several unrelated adversarial/session test timeouts.

Tara restores the original stricter budgets. The exact final Tara head passes the full Windows suite with those original budgets, so no safety/recovery timeout relaxation is required.

## Known performance-risk item

Session observability remains non-authoritative but currently persists synchronously on each metric mutation. A normal voice turn may perform several SQLite writes across STT, remote reasoning, TTS, and optional vision.

No automated regression currently demonstrates harmful overhead, and the combined suite is green. Nevertheless, Phase B real-user latency measurement should explicitly verify that observability persistence is negligible on Windows rather than assuming it is free.
