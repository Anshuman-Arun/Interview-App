## PRODUCT BUG

### Fixed in PR #118: configured duration had no runtime meaning

The New Interview flow accepts and persists `durationMinutes`, but current main never reads it during a live session.

PR #118 adds the minimal v0.1 behavior:
- persisted session creation time anchors the planned duration, including after recovery/restart;
- reaching the planned duration shows a clear non-blocking reminder;
- candidate work is never automatically terminated;
- the reminder is hidden while the live interview is backgrounded by Home;
- stored-session metadata is refreshed after start/recovery so the persisted creation time is available.

Quinn owns the New Interview setup surface now, so setup-page wording that explicitly describes the duration as a planning reminder is left for post-merge reconciliation rather than racing #119.

### Fixed in PR #118: user-facing implementation terminology

Review/history UI on main contains phrases such as:
- “authoritative event history”;
- “bounded product read limit”;
- “replay projection”;
- “bounded session projection(s)”;
- “grounded evaluator” in product-facing failure copy.

PR #118 replaces these presentation strings with ordinary user language without changing evaluator/replay authority, limits, or developer diagnostics. Tara backed out the overlapping `ReviewReadPanel.tsx` edits once Rachel began active work there; that page should receive the same copy pass during Phase B after Rachel merges.
