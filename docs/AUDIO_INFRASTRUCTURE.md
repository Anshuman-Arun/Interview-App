# Local audio infrastructure

This module is the mechanical browser audio layer for future local voice interviewing. It is intentionally non-authoritative: it owns devices, PCM frames, bounded buffering, playback resources, cancellation, and lifecycle only. It does not decide whether speech is a committed student turn, whether an interviewer generation is superseded, what was said, or what evidence is authoritative.

## Module structure

The implementation lives under `apps/web/src/audio/`.

- `types.ts` defines device, normalized frame, processor/source/sink, state, and typed error contracts.
- `devices.ts` enumerates browser audio input/output devices and exposes a leak-free `devicechange` subscription.
- `capture.ts` owns microphone `MediaStream` tracks and Web Audio resources and emits copied, browser-independent PCM frames.
- `bounded-buffer.ts` provides a fixed-capacity frame buffer.
- `cancellation.ts` provides idempotent AbortSignal-backed cancellation.
- `playback.ts` provides bounded sequential browser playback with cancellation and interruption.
- `renderer-adapter.ts` adapts queued playback to the existing renderer `AudioPlayer` seam without changing delivery state semantics.

## Device representation

Input and output devices are represented by device ID, optional label, explicit browser-default-alias status, kind, and availability. Each browser device record has its kind read once first. Non-audio records are discarded without touching unrelated ID/label metadata; audio records then snapshot their ID and label once before normalization, so stateful metadata getters cannot present different identities across the same enumeration result. The descriptor default flag recognizes the explicit `"default"` device ID only; an empty enumerated `MediaDeviceInfo.deviceId` is not guessed to mean default. Empty playback sink selection is still treated as ordinary default output because the media-element sink API defines an empty sink ID that way. Labels are optional because browsers commonly hide them before media permission is granted.

Enumeration returns explicit `AVAILABLE`, `PERMISSION_DENIED`, `UNSUPPORTED`, or `FAILED` states. The browser result must be an array of device records; malformed non-array results or primitive/null records are surfaced as `FAILED` rather than silently normalized into an empty successful enumeration. Error-name/message inspection is defensive: malformed rejected values fall back to a stable typed result instead of escaping while the manager is handling the failure. A device that was selected earlier but has disappeared can be represented with `unavailableAudioDevice(...)`.

Browser-global Audio/AudioContext constructors are snapshotted once before support checking/construction so stateful capability getters cannot change between detection and use; throwing capability getters are contained as typed `UNSUPPORTED` failures rather than escaping as generic playback/capture errors. Media-device capabilities are checked independently and verified to be callable at runtime; malformed non-function properties are treated as unsupported rather than invoked and misreported as operational failures. Capability property access itself is guarded as untrusted browser input, so throwing getters cannot escape the typed enumeration/subscription boundary. Missing `enumerateDevices` does not make microphone capture unavailable when `getUserMedia` exists, and missing `devicechange` event support is reported explicitly rather than silently installing a no-op subscription. Device-change callbacks are wrapped so synchronous throws or accidentally async rejections do not escape through the browser event loop. The wrapper stays inactive until browser listener installation returns successfully, so a browser shim that fires synchronously and then throws cannot deliver an observer callback for a subscription that ultimately failed. If listener installation throws after side-effecting, subscription keeps its wrapper inactive before attempting best-effort rollback; even if browser removal also fails and the listener remains physically attached, it can no longer call the user observer after `subscribe()` has failed. Unsubscription is marked inactive only after removal succeeds, so a transient cleanup exception does not make the listener permanently unretryable. A separate in-progress guard prevents reentrant browser removal code from recursively invoking the same unsubscribe while that removal is already executing.

Output-device selection is attempted only when a playback request explicitly asks for a non-default sink. Both the pseudo-device `"default"` and the empty sink ID use the browser's ordinary default output path and do not require `setSinkId` on a fresh element. If a factory later reuses an element on which this queue previously selected a non-default sink (or whose sink-selection outcome became uncertain during cancellation), the queue first waits for any older sink-switch promise on that physical element to settle, then explicitly resets that element with `setSinkId("")` before default-output playback. This prevents a late cancelled sink switch from resolving after the reset and re-routing newer audio back to the stale device; cancelling the newer item still breaks its wait immediately without requiring the browser's older sink promise to settle. If a non-default sink is requested, the `setSinkId` capability is snapshotted once before support checking/invocation; a missing capability fails with `OUTPUT_DEVICE_UNSUPPORTED`. A rejected sink selection maps `NotFoundError` to `DEVICE_UNAVAILABLE` and permission/policy rejection to `PERMISSION_DENIED`; other sink-switch failures remain `PLAYBACK_FAILED`. Playback-policy rejection from `play()` is likewise surfaced as `PERMISSION_DENIED` rather than an undifferentiated playback failure.

## Capture and normalized frames

`BrowserMicrophoneCapture` requests a selected input using `getUserMedia`, creates a Web Audio source and a small processing node, and copies each callback into an interleaved `Float32Array`.

Each `AudioFrame` contains:

- monotonically increasing sequence number within the current capture cycle;
- sample rate;
- channel count;
- capture timestamp;
- offset from the current capture start;
- copied interleaved PCM samples.

The AudioContext sample rate is snapshotted and validated once when the capture cycle starts. Before emitting a frame, the capture shim validates that each browser channel is actual `Float32Array` PCM, that the buffer reports the fixed sample rate and configured channel count for the cycle, at least one sample, no more samples per channel than the accepted capture frame size, equal sample counts across channels, and finite PCM sample values. Capture timestamps are required to be finite and nondecreasing within a capture cycle; clock regression fails capture rather than being hidden by clamping an invalid negative offset. Malformed buffers or clock values fail the capture generation instead of emitting apparently valid PCM with invalid metadata. The active operation token is also rechecked between capture-clock capability lookup and invocation, and after buffer format/channel reads and capture-clock access; if any of those untrusted reads reentrantly stop/dispose/supersede capture, normalization aborts and no late frame is delivered to `onFrame`.

No future speech component needs to retain the browser `MediaStream` or audio node objects. The array returned by `getAudioTracks()` is copied into capture-owned storage immediately after acquisition, so later mutation of a browser/caller-owned track array cannot remove a track from teardown ownership. If the browser creates the capture `AudioContext` in a suspended/interrupted state, the capture layer attempts to resume it before constructing the processing graph and does not report `CAPTURING` unless the context reaches `running`. Cancellation is checked before context-state inspection and again after untrusted state/resume capability reads, so a reentrant stop/dispose cannot still invoke `resume()` on a context already entering teardown. Resume policy rejection is typed as `PERMISSION_DENIED`; other resume failures are `CAPTURE_FAILED`. A stop/dispose can abort the wait for a pending resume and clean up the owned context without waiting for the browser resume promise to settle.

The current browser implementation uses `ScriptProcessorNode` as the narrow acquisition shim because it is available in the project's current browser target without introducing a separate worklet asset/protocol. It is deliberately hidden behind `CaptureAudioContextLike`; a later AudioWorklet migration can replace that shim without changing frame consumers, VAD, or STT boundaries.

Explicit frame sizes are restricted to the browser-valid ScriptProcessor sizes `256` through `16384` samples in powers of two, requested channel count is restricted to `1..32`, and an explicitly supplied microphone ID must be a string; non-empty whitespace-only IDs are rejected before browser access. Invalid configuration is rejected before microphone permission or hardware access is requested; malformed options are also rejected on an otherwise idempotent `start()` call while capture is already active rather than being silently ignored. The media-device object and `getUserMedia` capability are read defensively before a start operation is installed. Their lookup is guarded by the same lifecycle operation token as option admission, so a reentrant stop/dispose during capability access cannot be overwritten by the outer start; malformed getters remain typed pre-start failures.

Stop and disposal move state immediately to `STOPPED` / `DISPOSED`, while all already-owned cleanup promises are still awaited. Once `getUserMedia` has returned a stream, the in-progress setup is tracked as owned work too, so stop/dispose cannot resolve while partially constructed tracks/nodes/context are still being released. Every caller/browser-controlled setup step (track snapshot/state, context/node factories, listener registration, node connection/destination lookup, capture clock, and process-handler installation) is followed by the operation-token check; source/processor factories are also required to return objects with callable `connect`/`disconnect` methods before later graph setup proceeds; once a newer stop/dispose/restart supersedes the start, no later browser setup method is invoked and the existing partial-resource cleanup path takes over. Disposal is terminal even if it races a stop. A start waits for prior owned Web Audio cleanup before creating another context. Browser `getUserMedia` itself has no abort signal, but the capture layer does not keep a superseded caller waiting on that browser promise. Cancelling while an issued permission request is pending settles the stale `start()` promptly, keeps its acquisition-serialization slot reserved in the background, and stops any stream that later resolves without creating capture nodes. Late-stream cleanup attempts both `getAudioTracks()` and the standard `MediaStream.getTracks()` API with identity deduplication. That catches malformed/inconsistent late stream views where audio-track enumeration throws or returns an empty subset while the stream still exposes tracks, without double-stopping tracks returned by both methods. Replacement acquisition attempts therefore remain serialized behind the unresolved browser request, so stop/restart cannot create overlapping `getUserMedia` calls. A replacement that is only waiting for that serialization slot is likewise abortable and settles promptly when stopped/disposed. Empty-string and `"default"` input IDs are normalized to an unconstrained/default microphone request rather than an impossible exact-device constraint. Disposal does not wait for an unresolved browser permission prompt.

Capture options that affect an accepted start are snapshotted before asynchronous cleanup/acquisition begins. Start/restart also remember the lifecycle operation token from before those user-controlled option reads and recheck it both after a successful snapshot and when snapshotting throws. If an option getter reentrantly stops/fails/replaces capture, that lifecycle change wins even when a later option getter throws; the outer admission is abandoned instead of surfacing a stale validation/access failure. Disposal is rechecked as terminal. Restart performs the same snapshot and validation **before** stopping an active capture, so an invalid restart request cannot tear down healthy audio and caller-side mutation during cleanup cannot silently switch the selected device or callbacks. It also records the operation token created by its own stop and rechecks it after cleanup; any later stop/start/restart/failure therefore supersedes the older restart instead of allowing it to resurrect capture after the newer lifecycle command. If the frame consumer or frame construction fails, that capture generation fails once, releases its resources, and reports one `CAPTURE_FAILED` error instead of continuing to invoke a broken consumer at audio-frame frequency. The audio callback rechecks the lifecycle immediately after acquiring `event.inputBuffer`, so a getter that stops/disposes capture cannot cause subsequent reads from the returned buffer after processing has been cancelled. The public frame-consumer and error-observer seams remain synchronous for the real-time capture path. If a caller nevertheless supplies an `async` function (which TypeScript permits for a void-returning callback), capture detects returned promise-like values and observes rejection without awaiting them; observer failure never takes ownership of the capture lifecycle. A stream whose audio track is already ended is rejected before Web Audio nodes are created. If a track exposes `readyState`, only the browser-defined `"live"`/`"ended"` values are accepted; malformed states fail capture rather than being treated as implicitly live. Repeated references to the same physical track are collapsed by identity before lifecycle capability getters are read, so inspection, listener installation, stopping, and cleanup occur once per track object. Required track lifecycle methods (`stop`, ended-listener registration/removal) are verified before Web Audio construction, so a malformed stream cannot create a graph that the capture layer already knows it cannot manage safely. Track-ended events that occur synchronously anywhere during setup—including reentrant listener/handler installation—are latched and rechecked before resource publication, so `start()` cannot resolve successfully while the capture state is already `FAILED`. Cleanup promises are guarded before they are chained into the lifecycle tail, so one malformed browser cleanup cannot permanently poison every later start/restart attempt. Track-listener removal is also isolated from node/context release, so a malformed track collection cannot skip the remaining owned-resource cleanup.

## Buffering policy

`BoundedAudioFrameBuffer` has an explicit positive capacity stored behind getter-backed validated state, so ordinary runtime assignment cannot silently disable the bound. On overflow it **drops the oldest frame and accepts the newest frame**.

That policy is intentional for real-time speech: fresh audio is more useful than allowing a slow consumer to create unbounded latency or memory growth. Before queue mutation, the buffer first snapshots caller-owned frame metadata without assuming the runtime PCM field is already valid, copies any actual Float32 PCM into a fresh standard `Float32Array`, validates that exact owned copy (safe non-negative sequence, positive finite sample rate, positive channel count, finite timestamps/offset, complete interleaved non-empty PCM, and finite samples), and only then mutates the queue. This prevents stateful/hostile getters, typed-array species behavior, or concurrently changing shared PCM from producing stored samples that were never validated. A failed validation/copy therefore cannot evict valid buffered audio, and a producer cannot mutate audio after enqueue. Terminal cancellation is rechecked after the caller-controlled snapshot/validation boundary, so a frame getter that reentrantly cancels the buffer cannot repopulate it afterward; `peek()` and `snapshot()` also return defensive copies while `shift()` transfers ownership of the removed buffered frame. The push result returns the dropped frame so callers can count/report loss. `clear()` preserves reuse but invalidates any push that is still snapshotting/cloning caller-controlled frame data, so reentrant clearing cannot be undone by that in-flight push. `cancel()` is idempotent, clears all frames, and rejects future pushes.

## Playback and cancellation

`BrowserAudioPlayback` owns a bounded FIFO queue and at most one active HTML audio element. Its validated queue capacity is getter-backed rather than a writable JavaScript parameter property, so ordinary runtime assignment cannot turn the finite bound into `NaN`/unbounded admission. Its element factory receives no source URL; source attachment remains exclusively under the queue's lifecycle control. A media element cannot be handed to a later item while an earlier item's asynchronous setup coroutine still owns it; premature reuse fails the later item instead of allowing stale cleanup from the earlier item to scrub the new playback. `maxQueueSize` bounds the total pending work (the active item plus queued items); when full, new work is rejected with `QUEUE_FULL` rather than displacing audio that was already accepted.

Each accepted playback request is snapshotted before it enters the queue, including its identity, source, output selection, and callback set. Later caller-side mutation cannot retarget already-accepted audio. After the element factory returns, cancellation/disposal is rechecked immediately before any property on the returned element is inspected, so reentrant factory code cannot execute later browser getters or strand a cancelled element behind a pending sink switch. Output-selection and `play` methods are themselves snapshotted as untrusted browser properties and lifecycle is rechecked after each lookup, so a getter that cancels/disposes playback cannot still cause its returned method to run on a released element. Listener installation is likewise guarded around the registration-method lookup and rechecked after each registration; the matching listener-removal capability is snapshotted once before the first registration and retained with the pending item, so teardown does not depend on a later mutable property lookup; if the property getter or injected element code disposes/settles the item reentrantly, no later registration call is made, and any listener already added by a reentrant registration is explicitly removed before setup exits. For a non-default output, sink selection completes before the media source is attached; listeners are installed before source attachment so source-load failures cannot race ahead of the queue's error observation.

A playback handle exposes:

- `started`: resolves `true` only after the browser emits `playing`, or `false` if work terminates before exposure begins;
- `result`: resolves to `COMPLETED`, `CANCELLED`, `INTERRUPTED`, or `FAILED`;
- `cancel()`: idempotently cancels that item.

The playback controller also supports `interruptCurrent()`, `clearQueued()`, `cancelAll()`, and `dispose()`. Both `clearQueued()` and `cancelAll()` temporarily close playback admission while cancellation callbacks are being delivered, and `drain()` is suspended for the duration of those critical sections. This prevents a reentrant observer from repopulating the queue and, during `cancelAll()`, prevents cancelling the active item from promoting a queued item into current playback before that queued item is cancelled. `cancelAll()` settles the active item as `CANCELLED` before delivering queued cancellation observers, preventing a queued observer from reclassifying the active item as `INTERRUPTED`. Once cancelled or interrupted, listeners are detached and an eventual stale `ended` event cannot emit a successful completion callback. Pending `setSinkId()`/`play()` waits are raced against the item's terminal result, so cancellation/settlement releases the setup coroutine and re-scrubs its local element even if the browser operation never settles; the browser promise remains rejection-observed without retaining playback setup ownership. Handle cancellation is scoped to the exact accepted item, so an old settled handle cannot cancel a later item that reuses the same logical ID.

A browser `ended` event is accepted as successful completion only after a physical `playing` event for that item. An `ended` event received before start is treated as `PLAYBACK_FAILED`, so completion callbacks can never precede start callbacks.

Terminal state is settled and browser resources are detached before terminal observer callbacks run. The element's `pause` capability is snapshotted before playback begins and retained with the pending item, so physical cancellation does not depend on rereading a mutable method property after audio has started. Those observer callbacks are invoked exactly once and are not awaited by the mechanical queue, so a slow or rejected observer cannot leak the finished media element or block later playback.

Playback admission deliberately uses two owned snapshots rather than one full-request read. It snapshots and validates only identity first, then checks for an already-pending ID **before reading or validating any remaining payload fields or applying disposed/cancellation admission gates**. Only a unique, usable admission proceeds to a separate payload snapshot. Callback containers in that payload must be non-array objects with only the five declared callback keys; unknown keys are rejected from their key names before any corresponding callback getter is invoked, and only declared callbacks are then read once into owned storage. Malformed unique requests are rejected with typed `INVALID_REQUEST` (including blank/non-string identity/source, whitespace-only explicit sink IDs, callback arrays, unknown callback keys, malformed callback containers, or non-callable callbacks). Each top-level field is read at most once in its admission phase, so stateful/hostile accessors cannot present one value for validation and another for storage. The renderer adapter classifies those unique pre-enqueue validation failures as proven non-exposure because no playback item was admitted.

This identity-first ordering keeps same-ID ambiguity conservative even during synchronous teardown; only a unique ID proceeds to usability checks and a separate owned payload snapshot. Admission also reserves the validated ID until the request is either rejected or inserted into the queue. The reservation is released immediately after queue insertion and **before** `drain()` can invoke an element factory/browser hook, so a same-ID cancellation fired by that hook targets the real pending/current item instead of being lost as a stale admission cancellation. While caller-controlled identity/payload getters run, the queue records **which logical IDs** are accepted, settled, or explicitly cancelled; after the ID becomes known, only mutation of that same ID invalidates the admission. This preserves same-ID exposure/history conservatism without spuriously cancelling a unique request because an unrelated ID was cancelled, completed, or enqueued reentrantly. Once the reservation exists, `cancel(id)` also marks that specific in-flight admission cancelled; the outer enqueue then fails with `CANCELLED` before queue/element ownership, and the cancellation marker is cleared so later reuse of the same ID remains valid. Reentrant same-ID attempts therefore fail immediately as `DUPLICATE_ID` and can never briefly expose then disappear before the outer request finishes. The separate admission epoch is reserved for queue-wide invalidation such as `clearQueued()`/`cancelAll()`/disposal, which must invalidate every in-flight admission regardless of ID. This makes duplicate ambiguity dominate malformed-payload or queue-full classification: if the same ID is already pending/playing, the new attempt fails with typed `DUPLICATE_ID` even when its source/callback payload is malformed. `DUPLICATE_ID` is intentionally **not** translated to proven non-exposure because the existing same-ID item may already have exposed.

The renderer adapter maps only `started` and successful `completed` callbacks into the pre-existing delivery renderer contract. Definite pre-enqueue rejection such as a full/disposed player or malformed unique request is translated to the renderer's existing proven-non-exposure error, allowing the renderer-local DeliveryId entry to be safely retried. Cancellation-derived admission errors remain conservative rather than being reclassified: reentrant lifecycle changes can make exposure history ambiguous even when the outer request itself was not admitted. Ambiguous failures are not reclassified. Cancellation/interruption does not invent a delivery completion or change application-owned exposure semantics.

## Resource ownership

`BrowserMicrophoneCapture` owns each acquired stream during setup; browser track arrays are snapshotted incrementally, and fallback teardown walks independently addressable indexes so one malformed track slot cannot hide later tracks from cleanup. and every audio track, track-ended listener, source node, processor node, and AudioContext created for a start cycle. Stop, failure, restart, and disposal detach listeners/nodes, stop tracks, and close the context.

`BrowserAudioPlayback` owns each created HTML audio element and all of its listeners. Completion, failure, cancellation, interruption, and disposal remove listeners, pause playback, remove/clear the element source, reset position where supported, and release the element reference. If `removeAttribute("src")` is unavailable, throws, or even has a throwing property accessor, cleanup falls back to direct source clearing. Independent teardown operations are guarded so one browser cleanup exception cannot prevent the rest of cleanup or queue advancement.

Thrown/rejected browser values are treated as untrusted data. Error-name inspection is guarded so malformed accessors cannot strand capture in `STARTING` or leave a playback item permanently current. Capture also rechecks its operation token after error classification, so an error accessor that reentrantly stops/disposes capture cannot have that newer terminal lifecycle overwritten by the older failing start.

The opaque audio source string itself is caller-owned. In particular, if a future TTS layer creates a Blob/Object URL, that layer remains responsible for revoking it after the playback result; this module only owns media elements it creates.

Repeated stop/dispose/cancel calls are safe and do not re-fire callbacks. A stop invoked after disposal still waits for already-owned setup/cleanup work, rather than returning early solely because the terminal state was already set.

## Future pipeline boundaries

Input can evolve without changing capture ownership:

```text
MicrophoneCapture
      |
AudioFrameSource
      |
EchoCancellation
      |
VAD
      |
STT
      |
InputEpisode
```

`AudioFrameProcessor`, `AudioFrameSink`, and `AbortSignal` are the intended mechanical integration boundaries. This PR does not implement AEC, VAD, STT, endpointing, transcript creation, or `InputEpisode` creation.

Output can evolve as:

```text
TTS audio
   |
BrowserAudioPlayback
   |
started / completed / interrupted
```

This PR does not implement TTS generation or barge-in policy. A later runtime task must decide when an interruption semantically supersedes model work; this layer only stops physical playback when instructed.

## Hardware verification still required

Automated tests use fakes for media devices, streams, audio contexts, tracks, and audio elements. On a real target browser, manually verify:

1. permission prompt success and denial;
2. labels before and after permission;
3. selecting a non-default microphone;
4. unplugging/removing an active input device;
5. repeated capture start/stop cycles, including a browser session where a newly-created `AudioContext` begins suspended;
6. playback completion, cancellation, and interruption;
7. output-device selection on browsers that expose `setSinkId`;
8. cancellation while a microphone permission prompt is still open;
9. device-change behavior on any supported target browser that does not expose `devicechange` events.

No Silero VAD, Moonshine STT, Kokoro TTS, browser speech recognition, acoustic echo-cancellation policy, conversational endpointing, automatic turn commit, or Electron device integration is included here.
